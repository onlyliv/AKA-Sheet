# 첫 연결 데이터 보호 · 1.9.0-beta.1

## 동작

기존 정상 연결 기록(v2Initialized/legacyInitialized/firstSyncAccepted)이 없는 기기만 첫 연결 절차를 거친다. 미연결 상태의 데이터는 연결 시각의 최신 수정으로 취급하지 않는다. 양쪽 데이터가 있으면 로컬과 클라우드를 비교하고 승인 전 로컬 적용 및 업로드를 보류한다. 클라우드가 비었거나 기기가 비었으면 복구본을 저장하고 자동 진행한다.

첫 승인은 로컬 데이터와 클라우드 작업 그래프 해시에 묶인다. 검토 후 어느 쪽이든 바뀌면 새 요약을 확인한다. 편집/선택 작업 중에는 적용을 보류한다. 처음 가져오는 읽기 위치와 이미지 책의 작업 시각은 0으로 두어 연결 시각으로 최신성을 만들지 않는다. 이후 사용자의 정상 편집은 기존 작업 이력으로 처리한다.

읽기 위치와 삭제 기록은 클라우드를 유지한다. 주석/단어장/단어 ID가 충돌하면 로컬 변형을 별도 ID로 보존한다. 단어장 충돌은 자식 단어의 소속을 재연결한다. 동일 단어의 중복 판정은 기존 단어장 규칙(단어·뜻·예문 등)을 따른다. 전체 로컬 원본은 복구본에 보존한다. 이미지 책은 같은 ID의 클라우드 기록을 유지하고 로컬 원본은 복구본에 보관한다.

계정별 driveFirstBackup에 기기 원본, 클라우드 원본, 클라우드 작업 그래프와 이전 기기 저널을 먼저 저장한다. 복구본 쓰기에 실패하면 로컬 변경 및 업로드를 시작하지 않는다. 로컬 적용과 저널 저장은 기존 SyncApply 복구 트랜잭션을 사용한다. 승인 뒤 업로드 실패는 기존 영구 전송 대기로 재시도한다. 복구본은 브라우저에 있으며 사이트 데이터 삭제 전 내보내기가 필요하다. 이미 과거 버전에서 반영된 덮어쓰기/삭제를 자동으로 소급 복원하지 않는다.

## 검증

- 전체 자동 검사 56개 통과.
- 첫 계획 단위 검사: 클라우드 50페이지 대 로컬 3페이지, 삭제 부활 방지, 동일 ID 변형 보존, 단어장 소속, 결정적인 복사 ID, 빈 쪽 자동 진행.
- 실제 서버 서비스·인메모리 SQLite·가상 Drive를 연결한 기존 다기기 통합 검사 확장: 미연결 기기 사전 데이터, 승인 전 업로드 0회, 검토 중 로컬 변경/클라우드 변경 시 재검토, 복구본 저장 실패 시 무변경, 승인 후 병합 및 두 기기 수렴, 원본 양쪽 복구본 보존.
- 기존 오프라인 수정, 전송 중 수정, ACK 유실, 단일 대표 탭, 새 브라우저 복구와 삭제 후 재시작 검사 유지.
- Chrome 별도 로컬 origin의 실제 UI로 병합 요약/상세, 승인 전 업로드 0회, 버튼 승인 후 완료, 복구본 내보내기 UI 확인. 테스트 전용 DriveClient를 사용했으며 실제 Google 계정/사용자 데이터는 변경하지 않음.
- 브라우저 다운로드 완료 감시는 도구 시간 제한으로 미확인. 내보내기 형식/해시 검사와 원본 백업 저장은 자동 검사로 확인.
- 한국어·영어·일본어 문구 및 시작 리소스 51개, 서비스워커 캐시 검사.

## 범위

베타 브랜치와 전용 베타 Site만 수정. main 및 정식 Site는 유지. 실제 Google 계정 두 대와 iPhone 실기기에서의 신규 연결은 이번에 실행하지 않음.
