# UI internationalization

Versions: main1.1.0 / beta1.5.0-beta.1. Korean, English and Japanese UI.

- The Korean source message is the catalog key (gettext-style). `public/locales/messages.json` owns English/Japanese translations; Korean uses the source. Generate `catalog.js` with `node scripts/build-i18n.mjs public`. Placeholder names are validated.
- `public/i18n.js` resolves supported browser language preferences, defaults to English, and respects the device-local `aka.ui.language` override. Display language is not synced to Drive or included in learning data backups.
- Choose Settings → Menu UI → App display language. Preferences apply on the next launch; changing the selector never reloads a book or discards an active editor.
- Static UI uses explicit `data-i18n-*` bindings. App labels and error text use `I18n.t`/`I18n.error`. No DOM-wide translation observer or external translation API is used. Translations use textContent/attributes, never innerHTML.
- Books, recognized source text, note text, notebook names, dictionary senses and user vocabulary are not translated. Existing release history remains in its original language; release UI labels are localized.
- OCR/translation workers receive validated UI language through their URL. Service Worker cache lookup removes only uiLang, so a selected UI language does not break offline worker loading. Model policy and EPUB restrictions are unchanged.
- Date/time/number display uses the UI locale. OCR recognition language and translation/dictionary destinations keep their independent settings.

## Validation

`node tests/i18n.cjs` covers three locales, unsupported-language fallback, explicit overrides, workers, safe text binding, deferred preference changes, interpolation and catalog source coverage. `node tests/ocr-runtime-cache.cjs` verifies language-specific worker URLs load from prepared caches without network calls.

Browser checks: Korean initial UI; English menus and every settings tab; Japanese OCR settings; English390px responsive settings. Public main and beta are checked separately. Full native-speaker editorial review and physical mobile-device testing remain open.
